# 01. 실행환경 · 설치 · 사용자 매뉴얼

> 제주잇다 (Jeju-ITDA) — 관광객의 취향과 제주 상권을 데이터로 잇는 AI Agent 서비스
> 대상: 심사위원, 제주빅데이터센터 PC에서 직접 실행할 운영자

---

## 1. 구성 한눈에 보기

| 구성 | 폴더 | 기술 | 역할 |
|---|---|---|---|
| 백엔드 (Agent 서버) | `backend/` | Python 3.11+, FastAPI | Agent 실행, 제주데이터허브 연동, GPT 호출, 로그인, 데이터 저장(SQLite) |
| 웹 | `frontend/` | React 18 + Vite 5 | 관광객·상권 주인·관리자 화면 |
| 모바일 앱 | `app/` | Flutter (Android·iOS) | 웹과 같은 화면·기능 |
| 배포 | `compose.yaml`, `backend/Dockerfile`, `deploy/frontend/` | Docker Compose, nginx | 서버 한 대에서 백엔드+웹 실행 |

**외부 키는 모두 백엔드 `.env` 에만** 둡니다. 웹·앱에는 카카오맵 JavaScript 키(브라우저 공개용)만 넣습니다.

## 3. 설치 · 실행

### 3-1. 백엔드 (필수)

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate            # macOS·Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env             # macOS·Linux: cp .env.example .env
```

`.env` 를 열어 키를 채웁니다 (아래 4장). 그다음:

```bash
uvicorn app.main:app --port 8000
```

| 확인 주소 | 내용 |
|---|---|
| http://localhost:8000/api/v1/health | `{"ok": true, "gpt_enabled": true, "jeju_data_hub_connected": true, ...}` |
| http://localhost:8000/docs | 전체 API 문서 (Swagger) |

서버를 켜면 백그라운드에서 제주데이터허브 유동인구를 받아 **지역 혼잡도**를 계산합니다(1~2분).
그동안에도 코스 추천은 혼잡도 없이 동작합니다.

### 3-2. 웹

```bash
cd frontend
npm install
copy .env.example .env             # macOS·Linux: cp .env.example .env
```

`.env` 에서 내 PC 백엔드를 쓰려면 `VITE_PROXY_TARGET=http://localhost:8000`, `VITE_USE_MOCK=false` 로 둡니다.

```bash
npm run dev                         # http://localhost:5173
npm run build                       # 배포용 정적 파일 → frontend/dist/
```

### 3-3. 모바일 앱 (선택)

```bash
cd app
copy env.example.json env.json      # 값 채우기 (아래 4장)
flutter pub get
flutter run --dart-define-from-file=env.json
```

안드로이드 에뮬레이터에서 내 PC 백엔드를 쓰려면 `API_BASE_URL` 을 `http://10.0.2.2:8000/api/v1` 로 둡니다.

### 3-4. Docker 로 서버 한 대에 배포 (선택)

```bash
docker compose up -d --build        # 프로젝트 루트에서
docker compose ps                   # 상태
docker compose logs --tail=100 backend
```

- `backend` 컨테이너: `backend/.env` 를 읽고, DB·캐시는 `backend/storage/` 볼륨에 저장
- `frontend` 컨테이너: nginx 가 웹 화면을 주고 `/api`·`/ws`·`/docs` 를 백엔드로 중계
- `compose.yaml` 은 외부 Docker 네트워크 `compose_default`(Nginx Proxy Manager)에 붙도록 되어 있습니다.
  프록시가 없는 PC에서는 `networks` 항목을 지우고 `ports: ["8000:8000"]`, `["80:80"]` 을 추가하세요.

## 4. 환경 변수 예시

### 4-1. 백엔드 `backend/.env` (원본: `backend/.env.example`)

```ini

# 제주데이터허브 — 허브 마이페이지 > 프로젝트 관리 > 프로젝트키
JEJU_DATA_HUB_API_KEY=
JEJU_DATA_HUB_BASE_URL=https://open.jejudatahub.net/api/proxy

# 실시간 날씨 — 비우면 Open-Meteo(키 없음)

NAVER_CLIENT_ID=
NAVER_CLIENT_SECRET=

# 카카오 Local REST 키 (주소·키워드 검색) — 비우면 보유 좌표로 계산
KAKAO_REST_API_KEY=
```

## 5. 사용자 매뉴얼

### 5-1. 시연 계정 (처음 실행 시 자동 생성, 비밀번호 `jeju1234`)

| 이메일 | 역할 | 들어가는 화면 |
|---|---|---|
| `user@jeju.kr` | 관광객 | 여행 코스 |
| `owner@jeju.kr` | 상권 주인 | 내 가게 |
| `sehwa@jeju.kr` | 상권 주인 (승인 대기) | 로그인 불가 → 관리자 승인 시연용 |
| `admin@jeju.kr` | 관리자 | 관리 콘솔 + 모든 화면 |

같은 설정에서 개발용 테스트 계정도 만들어집니다 (비밀번호 = 이메일 앞부분):
`a123@test.kr`(관광객) · `b123@test.kr`(상권 주인) · `c123@test.kr`(관리자).
**운영·센터 PC 반입 시에는 `.env` 에 `SEED_DEMO_ACCOUNTS=false` 로 두고, 이미 만들어진 계정은 관리 콘솔에서 정지하세요.**

새 계정은 `회원가입` 으로 만듭니다. 관광객은 바로 사용, 상권 주인은 관리자 승인 후 사용합니다.

### 5-2. 관광객

1. **성향 테스트** — 12문항에 답하면 4축(액티비티↔힐링, 자연·바다↔도심, 미식↔풍경, 계획↔즉흥) 점수로 16유형 중 하나가 나옵니다 (예: "노을 감성 탐험가"). 동행·이동수단·출발 시각·이용 시간도 고릅니다.
2. **출발 지역** — 지도에서 지역을 누르거나 `현재 위치 사용`.
3. **AI 코스** — 시간표 형태의 3~5곳 코스. 장소마다 *왜 추천했는지* 데이터 근거가 붙습니다 (예: "읍면동 방문인구 하루 98,418명 · 제주 평균 대비 -12% → 혼잡도 낮음 (실측)"). 실시간 날씨가 비·눈이면 실내 코스로 시작합니다.
   - 대화로 고치기: "저녁은 회 먹고 싶어", "실내 위주로", "1곳 줄여줘", "함덕 해변 빼줘"
   - `다른 코스 보기`: 지금까지 본 장소와 겹치지 않는 코스를 Agent 가 새로 고릅니다.
4. **방문 후 평가** — 장소별 별점 + 한 줄 평. 평가는 곧바로 그 가게 사장님 화면과 지역 점수에 반영됩니다.

### 5-3. 상권 주인

1. 처음 로그인하면 **내 가게 연결** — 관광객이 실제로 평점을 남긴 장소 목록에서 내 가게를 고릅니다.
2. **내 가게 화면** — 별점 평균·리뷰·어떤 성향의 손님이 왔는지, 지역 점수.
3. **리뷰 주제별 반응 (Agent)** — GPT 가 리뷰를 읽고 맛·가격·대기 시간 등 주제별 긍정률과 한 줄 요약을 만듭니다.
4. **리뷰 분석 보고서 (Agent)** — 강점·개선할 점·다음 주에 해 볼 일을 정리해 저장합니다.
5. **AI에게 물어보기** — "평일 저녁 손님을 늘리려면?" 처럼 질문하면 내 가게 평가를 근거로 답합니다.
6. **메뉴·이벤트 등록** — 개선 조치를 등록하면 효과 측정(MEASURING) 상태로 저장됩니다.
7. 새 평가가 들어오면 화면에 실시간 알림이 옵니다.

### 5-4. 관리자 (제주시 Main PC 콘솔)

| 탭 | 내용 |
|---|---|
| 통합 현황 | 오늘 방문 인증·평가·코스 선택 수, 실시간 이벤트 피드(WebSocket), 지역 점수 지도 |
| 지역 인사이트 | 지역 점수 0~10 (만족도 50% · 수요 30% · 쾌적함 20%), **Agent 지역 보고서** 작성·보관 |
| 데이터 관리 | 원천 데이터 적재 이력(데이터허브 API 11종의 최신 날짜·받은 시각·건수·오류, 받아 둔 파일), 생성 데이터, 품질 점검 |
| 접근·보안 | 계정 승인·정지, 조회·로그인 기록, 개인정보 마스킹 규칙 |
| 백업·복구 | SQLite 스냅샷 생성, **관리자 2명이 요청해야** 실행되는 복구 |

## 6. 오류 · 제약사항

### 6-1. 자주 나는 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| `/health` 의 `gpt_enabled` 가 true 인데 AI 답이 규칙 문장 | 키가 틀렸거나(401), 모델 이름이 없음(404 `model_not_found`) | `.env` 의 `OPENAI_API_KEY` 확인, `OPENAI_MODEL` 을 이 계정에서 쓸 수 있는 모델로. 서버 로그의 `OpenAI API 오류` 확인 |
| 코스 근거에 "실측" 문장이 없음 | 서버 시작 직후 혼잡도 계산 중, 또는 허브 일시 오류 | 1~2분 뒤 다시. 실패 시 서버가 1분 간격으로 5번 재시도 |
| `DATAHUB_ERROR` (502) | 제주데이터허브가 같은 요청에도 500/502 를 자주 돌려줌 | 서버가 6번 재시도하고, 날짜를 비운 요청은 하루씩 앞 날짜로 물러남. 계속되면 잠시 후 다시 |
| `TOO_MANY_REQUESTS` (429) | 허브 데이터별 하루 호출 950회 도달 (허브 한도 1,000) | 다음 날 또는 캐시된 날짜로 조회 |
| 지도 자리에 안내 문구만 | 카카오 JavaScript 키 없음 / 도메인 미등록 | 카카오 콘솔 > 플랫폼 > Web 에 주소 등록, 카카오맵 활성화 |
| 로그인 시 `ACCOUNT_PENDING` | 상권 주인 승인 전 | 관리자 > 접근·보안 > 가입 승인 |
| 내 가게 화면에 `PLACE_NOT_LINKED` | 가게 연결 전 | 내 가게 연결 (관광객 평점이 있는 장소만 가능) |
| `flutter pub get` 실패 (SDK version) | Flutter 3.50.0 미만 | Flutter 업그레이드 |

오류 응답은 모두 `{ "error": { "code": "...", "message": "..." } }` 형식입니다.

### 6-2. 제약사항

- **데이터 시점**: 허브 유동인구는 약 2~3개월 늦게 올라옵니다(2026-11 기준 최신 2026-08-31). 관광지 유입은 2024-12, 허브 기상은 2025-03 까지라 실시간 날씨는 기상청/Open-Meteo 를 씁니다.
- **장소 목록**: 추천 후보는 실제 제주 장소 37곳을 직접 정리한 목록입니다. 상가·음식점 원천 데이터(받아 둔 파일)로 후보를 넓히는 작업은 하지 않았습니다.
- **상권 지표**: 사장님 화면은 앱에서 관광객이 남긴 실제 평가로만 계산합니다. 평가가 없으면 비어 있습니다 (카드 매출 등 매장 단위 데이터는 센터 데이터 반입 후 연결 예정).
- **대화 상태**: 코스 대화 중 기억한 선호(바다 보이는 카페 등)는 서버 메모리에 있어 서버를 다시 켜면 비워집니다.
- **GPT 사용 범위**: GPT 에는 숫자 대신 등급(낮음/보통/높음)과 앱 평가 텍스트만 보냅니다. 허브 원본 행은 보내지 않습니다. 다만 외부 API 이므로, 인터넷이 막힌 센터 PC에서는 GPT 기능이 규칙 기반으로 바뀝니다 (서비스는 계속 동작).
- **단일 서버**: uvicorn 프로세스 1개 기준입니다 (대화 상태·이벤트 방송이 메모리 기반).
